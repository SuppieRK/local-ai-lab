# Contributing

Contributions are welcome. So are forks. So are strong opinions backed by working code.

## Before You Open a PR

- Make sure it actually works.
- Make sure it does not introduce 17 new abstractions.
- If it adds blockchain-based GPU orchestration with on-chain inference validation, please reconsider your life choices.

## What Is Appreciated

- Small, focused improvements.
- Clear documentation.
- Fixes that remove complexity rather than add it.
- Scripts that do one thing and do it predictably.

## What Is Probably Out of Scope

- Turning this into a framework.
- Turning this into a platform.
- Turning this into a startup idea.
- Adding a dependency tree that requires its own GPU.

## Style

Prefer boring over clever.  
Prefer explicit over magical.  
Prefer fewer moving parts over impressive diagrams.

If in doubt, open an issue first. Or fork it and run your own experiment.

Both are valid engineering strategies.
